# エージェント検証ハーネス

目的: Copilot / Codex / Claudeの実装結果を、既存検証の実行証拠で確認する。
AIサービスやモデルの選択に依存せず、外部APIキーは不要。

## 実行

リポジトリの依存関係を通常どおり準備し、変更を作業ブランチへコミットしてから:

```sh
python3 tools/agent-harness/run.py --output /tmp/agent-harness-evidence
```

WindowsではPythonとNode.jsをPATHへ追加し、出力先をチェックアウト外に指定する。
GitHub ActionsはPR更新時と手動起動時に同じ入口を実行する。定期監視は追加しない。
`config.json`の各コマンドをシェル展開せず実行し、失敗後も残りを実行する。
未導入コマンド、タイムアウト、空の設定、重複ID、未コミット変更は合格にならない。
記録は対象SHA、実行時刻、コマンド、終了コード、所要時間、出力末尾。
クリーンな作業ツリーと全チェック成功で自動検証はpassed。`release_ready`は常にfalse。
出力はチェックアウト外へ保存し、CIの実行サマリーと14日保存のartifactで確認する。

## 人とAIの分担

実装担当は既存タスク/PRを継続。レビュー担当は最新SHAの差分・実行証拠・案件固有項目を確認する。
独立したセッションでレビューする場合も対象SHAを固定し、指摘にはファイルと再現手順を添える。
並列作業はリポジトリ/ブランチを分け、同じファイルの編集は直列化。
修正→再検証は最大2回。その後は失敗理由と次の作業を報告する。
既存のCI・レビュー・公開承認・業務検収を省略しない。

## Copilot製品側の導入境界

`.github/copilot-instructions.md`で同じ手順をCopilotへ渡す。
Fusion、Projects、Review Maxの契約・利用可否・有効化は別途アカウントで確認が必要。
このPRはそれらの有効化や課金設定変更を行わない。
利用できる場合、案件ごとの既存リポジトリをProjectsへ追加し、本手順と既存ルールを文脈として渡す。
モデルは利用可能な設定を使い、特定モデル名をハードコードしない。
既存監視と同じ通知や修正PRを増やさない。試行3件で確認時間・有効な指摘数・実費を比較する。

## 案件固有の確認

- 記事本文・一次資料・専門家レビューの状態を確認。機械検証成功を事実照合済みと扱わない。
- 公開状態、dateModified、sitemap、content-inventory、keyword-mapの変更理由と整合性を確認。
- UI変更は320px/375px/390pxで確認。
